# Chapter alignment and limits of the public companion

This repository accompanies *Hybrid Deep Learning for Space-Debris Radar
Tracklet Reconstruction*. It distributes method code, not the thesis text,
the underlying benchmark, a simulator, or a complete historical experiment archive.

| Chapter topic | Public implementation | Scope |
| --- | --- | --- |
| Windowed estimation, zero-based indices | `workflows.window_arrays` | Inputs 0–24; target 25; 294 pairs for 319 records |
| Input features and standardisation | `preprocessing`, `workflows.prepare_windows` | Eight elevation, nine range, six pivot-azimuth features; training-only scaling |
| Direct elevation | `build_elevation_features_and_target`, `evaluation.reconstruct` | Ordinary angular difference; rad converted to mrad |
| Causal residual range | `causal_poly_forecast`, `causal_poly_residual` | Quadratic fitting on sample indices; no target-time measurement |
| Pivot azimuth | `build_azimuth_windows` | Measured first-window pivot restored after inverse scaling |
| Architecture/readout | `models.build_window_model` | MLP, CNN, GRU, GRU–CNN; explicit family selection |
| Final streaming azimuth | `models.build_final_azimuth`, `streaming` | GRU 256, Dense 64, Dense 1; batch 8, chunks 25, no CNN |
| Final azimuth fitting | `training.fit_final_azimuth` | Focused Huber-d2; validation physical RMSE selects weights; no test input |
| Physical metrics | `evaluation`, `streaming.physical_predictions` | Pooled errors; only azimuth uses circular differences |

## Numerical results are not regenerated by inclusion of code

The historical architecture table, disturbance-profile table, favourable
UKF examples (75.8%, 55.6%, 96.1%), elevation checkpoint at epoch 87,
hardware timings and historical hyperparameter searches are **not reproduced
or independently certified by this release**. Their exact trained weights,
search logs, split supports and sample-level outputs are not distributed.
The architecture constructors describe the available working implementation;
they are not asserted to be the exact tuned configuration behind every
published table entry. The original working notebooks were excluded because
they mix later experiments, older settings and plotting paths.

The chapter's seed-42 final azimuth value (1.8695 mrad over 439,824 targets
from 1,496 trajectories) is a reported audit result, not a score generated by
the public tests. Re-evaluation requires privately supplied weights, the
original scalers, trajectory lists and data. No comparison in this release
establishes that statefulness alone caused the improvement.

Historical test-independent architecture selection for elevation/range is
not reconstructible from the currently archived validation material. The
chapter's general statements about selection do not replace those missing
records. This release does not manufacture search logs or select a model
from historical test scores.

## Precise implementation qualifications

- Range baseline: at most 25 noisy values through input index t, quadratic
  `numpy.polyfit` on absolute sample indices and extrapolation at t+1.
  At startup the degree is reduced; a single observation gives persistence.
- Local range residual at t: current noisy range minus a polynomial forecast
  fitted to at most 24 **previous** noisy samples, excluding t from that fit.
  Insufficient history yields zero. This is an input feature, not clean noise.
- Azimuth's names `angular_velocity` and `angular_acceleration` denote first
  and second angular differences per sample. No division by timestamp delta
  occurs. The baseline adds the median of at most seven previous/current
  wrapped increments to the current measured azimuth. This assumes the
  nominal near-one-second cadence; it is not a variable-dt implementation.
- Elevation's azimuth differences are ordinary differences; range/azimuth
  branches unwrap azimuth. These are source-code semantics, not interchangeable.
- The clean sequence never enters predictor features or recurrent feedback.
  There is no autoregressive teacher forcing in the distributed paths.
- `same` convolution is bidirectional only inside the observed window.
  The hybrid GRU returns sequences; the plain GRU returns the final state.
- Streaming targets begin at original index 1. Evaluation starts at target
  index 25 after a 25-sample observation history; the eligible final index is
  318 for a 319-record trajectory. Earlier real inputs build recurrent state.
- Padded positions have zero training weights. Metrics separately select
  positive weights, finite baseline/reference and target index >=25.
  Standard Keras weighted-loss reduction need not divide by the number of
  valid positions; zero-weight padding contributes no error term, but can
  still affect the loss denominator. Physical metrics use valid positions.
- Streaming groups keep eight trajectories in fixed slots. Incomplete final
  groups are omitted, and groups stop at their shortest chunk count.
  For the complete equal-length benchmark, 1,500 trajectories yield 1,496
  retained trajectories. This is not a general guarantee for arbitrary data.
- Recurrent state survives chunk boundaries, but each training batch has a
  separate gradient update: gradients do not propagate across prior batches.
- An external posterior UKF uses a target-time measurement. It is not a
  matched-information one-step forecast. Its full initialization, covariance
  and update implementation are not supplied, so no replacement UKF is
  silently introduced and no UKF percentage is recomputed here.

## What is intentionally not included

No benchmark CSVs, dataset identifiers/manifests, per-sample/per-trajectory
exports, scalers, learned weights, simulation code, private filesystem paths,
historical figures, manually entered result curves, or thesis/paper PDFs.
Tests use arbitrary small numerical arrays only; these are not an orbital
simulator and provide no evidence of real-world forecasting performance.
